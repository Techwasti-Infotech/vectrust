Pure Rust Embedded Engine • 2026 Edition

Embedded Vector Database Engine for Rust

Sub-millisecond approximate nearest neighbor search powered by HNSW graphs, SIMD-accelerated distance metrics, deep JSON predicate filtering, and atomic crash-resilient WAL persistence. Runs directly inside your application process with zero external network dependencies.

🚀

HNSW Proximity Graph

Hierarchical multi-layer graph index with $O(\log N)$ scaling, configurable $M$, $M_0$, and $ef$ search beam depth.

⚡

SIMD Distance Metrics

8-way loop unrolled vector calculation for Cosine, Euclidean ($L_2$), Dot Product ($MIPS$), and Manhattan ($L_1$).

🛡️

Crash-Proof Persistence

Write-Ahead Log (WAL) journal and atomic snapshot engine with CRC32 integrity verification and self-healing replay.

🔍

Deep Metadata Filtering

Boolean predicate engine with nested dot-notation paths (`user.tier`), range comparisons, and filter-aware graph traversal.

🚀 Quickstart Guide

Get started with Vectrust in under 60 seconds.

1. Add Vectrust to Cargo.toml

[dependencies]
vectrust = "0.1.0"
serde_json = "1.0"

2. Basic Ingestion & Search Example

use serde_json::json;
use vectrust::prelude::*;

fn main() -> vectrust::Result<()> {
    // 1. Initialize embedded database (in-memory or persistent path)
    let db = Vectrust::open("./data/my_vectrust_db")?;

    // 2. Configure a 4-dimensional collection with Cosine similarity
    let config = CollectionConfig::builder(4, Metric::Cosine)
        .index_type(IndexType::Hnsw)
        .build();

    let collection = db.get_or_create_collection("articles", config)?;

    // 3. Insert vectors with structured JSON metadata
    collection.insert(
        Point::new(101u64, vec![0.92, 0.12, 0.35, 0.08]).with_payload(json!({
            "title": "High-Performance Rust Vector Databases",
            "category": "systems",
            "views": 5420
        })),
    )?;

    collection.insert(
        Point::new(102u64, vec![0.15, 0.88, 0.04, 0.45]).with_payload(json!({
            "title": "Modern Frontend Micro-Frontends",
            "category": "web",
            "views": 1280
        })),
    )?;

    // 4. Query nearest neighbors with metadata pre-filtering
    let query_vector = vec![0.89, 0.15, 0.32, 0.10];
    let query = SearchQuery::new(query_vector, 5)
        .with_filter(Filter::and(vec![
            Filter::eq("category", "systems"),
            Filter::gte("views", 1000),
        ]))
        .include_payload(true);

    let results = collection.search(query)?;

    for match_item in results {
        println!(
            "Matched Point ID: {} | Score: {:.4} | Title: {}",
            match_item.id,
            match_item.score,
            match_item.payload.unwrap()["title"]
        );
    }

    // Flush and compact WAL snapshot to disk
    db.flush_all()?;
    Ok(())
}

🏗️ Architecture & Storage Engine

Vectrust is designed with a layered, zero-poisoning concurrent architecture:

flowchart TD UserApp["User Application / Agent / RAG Pipeline"] --> Vectrust["Vectrust Embedded DB"] Vectrust --> Collection["Collection: Thread-Safe Arc / RwLock"] subgraph EngineCore ["Engine Core"] Collection --> HNSW["HNSW Graph Index (ANN)"] Collection --> Flat["Flat Linear Index (Exact)"] Collection --> Filter["Metadata & JSON Filter Engine"] end subgraph DistanceSIMD ["Distance & SIMD"] HNSW --> Dist["Vectorized Distance: L2 / Cosine / Dot / L1"] Flat --> Dist end subgraph StorageDurability ["Storage & Durability"] Collection --> WAL["Write-Ahead Log: Append-Only Journal"] Collection --> Snapshot["Atomic Snapshot Engine: CRC32 Verified"] end
💡
Thread Safety & Concurrency: Vectrust uses parking_lot::RwLock without poisoning. Thousands of concurrent reader threads can query the index simultaneously without contention while mutating writes log sequentially to the WAL.

🕸️ HNSW Proximity Graph Mechanics

Vectrust implements the Hierarchical Navigable Small World proximity graph model based on Malkov & Yashunin (2018). Each point is assigned an integer layer sampled exponentially:

level = floor(-ln(uniform(0, 1)) * (1.0 / ln(M)))

Higher layers act as express lanes with long-range skips ($O(\log N)$ routing), while layer 0 contains the dense, local nearest neighbors.

Tuning Parameters

Parameter Default Range Impact
m 16 8 – 64 Max outgoing edges per node on upper layers. Higher values improve recall on high-dimensional vectors at the expense of memory.
m0 32 $2 \times M$ Max outgoing edges on layer 0. Doubled to maintain dense ground connectivity.
ef_construction 100 40 – 400 Search depth during index construction. Higher values yield a higher quality graph at the cost of slower build time.
ef_search 64 10 – 300 Search depth during runtime queries. Can be overridden dynamically on a per-query basis via SearchQuery::with_ef_search().

🔍 Deep Metadata Filtering

Vectrust supports JSON metadata pre-filtering directly during search. It inspects nested properties via dot-notation without deserializing into rigid schemas.

use vectrust::prelude::*;

// Nested predicates and boolean compositions
let filter = Filter::and(vec![
    Filter::eq("user.status", "active"),
    Filter::in_list("region", vec!["us-east", "eu-central"]),
    Filter::gte("metadata.tier", 2),
    Filter::contains("tags", "enterprise"),
    Filter::not(Filter::eq("is_archived", true)),
]);

let query = SearchQuery::new(vec![0.1, 0.5, 0.8, 0.2], 10)
    .with_filter(filter);

let results = collection.search(query)?;
